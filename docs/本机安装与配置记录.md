# Ubuntu KDE/Wayland 安装与配置记录

## 环境与结果

- x86_64，Ubuntu 26.04.1 LTS，KDE/Wayland。
- Fcitx5 5.1.19，系统已在使用 Fcitx5，无需替换输入法框架。
- 上游基础提交：`879bbe8`。
- 完成用户级安装，临时词库自检通过：启动、输入、选词、学习、空闲 85 秒后继续输入及重启后保留学习结果。
- 已关联手机，启用云候选、个人词库增量同步和常用语刷新。
- 剪贴板互通保持关闭。
- 候选框固定浅色；单按 Shift 切换中英文关闭，Shift 大写输入保留。

这是一次本机安装记录，不代表所有 KDE/Wayland 应用都已验证。新机器装好后仍需在实际文本框试打。

## 依赖与构建

常规依赖见[安装与使用](安装与使用.md)。本机缺少 `libfcitx5core-dev` 和 QEMU，由用户安装：

```sh
sudo apt install libfcitx5core-dev qemu-user
```

本机软件源没有 `qemu-user-static` 候选包，但 `qemu-user` 提供的
`/usr/bin/qemu-aarch64` 经 `file -L` 确认为 `static-pie linked`，可通过现有环境变量指定：

```sh
bash scripts/prepare_ndk.sh
export ANDROID_NDK_HOME="$PWD/.deps/tools/android-ndk-r27c"
export QEMU_AARCH64=/usr/bin/qemu-aarch64
bash scripts/e2_img.sh
./WeTypeIME-Engine-x86_64.AppImage install --user
```

NDK 下载后验证脚本固定的校验值。安装器下载并校验官方 3.5.4 APK，再在本机修补引擎。安装不需要 sudo，但会写入用户级 Fcitx5 插件注册文件并请求配置重载。

## 启用输入法与自检

退出 Fcitx5 并确认进程已停止，备份 `~/.config/fcitx5/profile`，在默认分组中按现有最大序号加一追加：

```ini
[Groups/0/Items/N]
Name=wetype-im
Layout=
```

`N` 是占位符，不要直接照抄。保留现有输入法条目，不替换整个 profile。

```sh
fcitx5 -d
fcitx5-remote -s wetype-im
fcitx5-remote -n
python3 scripts/test_bionic_daemon.py \
  --engine-dir ~/.local/lib/wetype-ime/arm64 --idle-seconds 85
```

自检输出 `E2E_RESULT = PASS`。桌面没有聚焦输入框时，`fcitx5-remote -n` 可能为空；最终聚焦后确认输出 `wetype-im`，仍需人工试打 `nihao`。

## 手机关联与云功能

本机 Node.js 22 满足工具要求：

```sh
npm install --prefix "$HOME/.local/share/wetype-ime/tools" @mkdir700/wxc@0.1.0
python3 ~/.local/lib/wetype-ime/arm64/wetype-cloud.py pair --name "Linux 输入法"
```

手机入口位于微信输入法设置中的“跨设备粘贴和同步”，具体文字随客户端版本变化。
取得六位关联码后，在终端交互输入，并在手机确认。不要把关联码写入文档或提交记录。

征得用户同意后启用云服务并重启 Fcitx5：

```sh
python3 ~/.local/lib/wetype-ime/arm64/wetype-cloud.py enable --timer
python3 ~/.local/lib/wetype-ime/arm64/wetype-cloud.py status
systemctl --user is-active wetype-sync.timer
python3 ~/.local/lib/wetype-ime/arm64/wetype-cloud.py clipboard status
```

本机检查得到 `paired=true`、`cloud_enabled=true`，定时任务为 `active`，剪贴板为
`enabled=false`、`running=false`。云候选会发送正在输入的拼音，词库同步会发送新学词条；
常用语只读取。启用云功能不会自动打开剪贴板互通。关联前的历史学习数据不保证自动补齐，
需要时另按[恢复历史词库](恢复历史词库.md)处理。

## 固定浅色候选框

备份 `~/.config/fcitx5/conf/classicui.conf`，将以下选项写入配置，其他选项保留：

```ini
Theme=default
DarkTheme=default
UseDarkTheme=False
```

这只调整 Fcitx5 经典候选框，不修改 KDE 的全局主题。

## 关闭单按 Shift 切换

原插件把 Shift 切换写死。本次增加 `ShiftToggle` 布尔配置项，默认 `True` 保持原有行为。
在“微信拼音”的配置中取消“单按 Shift 切换中英文”，或在
`~/.config/fcitx5/conf/wetype.conf` 设置：

```ini
ShiftToggle=False
```

修改源码后的部署步骤：

```sh
bash fcitx5-wetype/build.sh
ctest --test-dir fcitx5-wetype/build --output-on-failure
# 退出 Fcitx5，确认进程停止，备份原插件后再替换
install -m 755 fcitx5-wetype/build/libfcitx5-wetype.so \
  ~/.local/lib/fcitx5/libfcitx5-wetype.so
fcitx5 -d
```

本机五项 C++ 单元测试通过。重启后用 Fcitx5 D-Bus `GetConfig` 检查时，最初读到旧值，
随后通过配置接口显式应用并保存，最终确认 `ShiftToggle=False`、`Theme=default`、
`UseDarkTheme=False`。若手工编辑后未生效，可在设置界面应用，或用配置接口：

```sh
gdbus call --session --dest org.fcitx.Fcitx5 --object-path /controller \
  --method org.fcitx.Fcitx.Controller1.SetConfig fcitx://config/addon/wetype \
  "<{'ShiftToggle': <'False'>}>"
gdbus call --session --dest org.fcitx.Fcitx5 --object-path /controller \
  --method org.fcitx.Fcitx.Controller1.SetConfig fcitx://config/addon/classicui \
  "<{'Theme': <'default'>, 'DarkTheme': <'default'>, 'UseDarkTheme': <'False'>}>"
```

关闭后 Shift 不再切换微信输入法内部模式，但大写和组合键照常。
Ctrl+Space 仍由 Fcitx5 的全局配置决定，可用于输入法与英文键盘切换。
配置和原插件均在原路径旁创建带时间戳的备份。

## 搬到另一台机器

本次最初生成的 AppImage 早于 Shift 开关改动，里面仍是旧插件。
要分发修改后的版本，应在这个提交的源码上重新运行 `scripts/e2_img.sh`。
新机器需为兼容的 x86_64 Linux，安装并启用 Fcitx5，然后运行 AppImage 的
`install --user`，添加“微信拼音”。安装时仍需下载官方 APK。

主题及 `ShiftToggle=False` 是用户配置，不随 AppImage 自动迁移，需在新机器单独设置。
云功能也需单独关联设备，不能复制 `~/.local/state/wetype-ime/account`。
不要把个人词库、账号目录、输入日志或本机配置备份提交到仓库。
